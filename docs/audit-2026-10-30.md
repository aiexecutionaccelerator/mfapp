# App audit — 30 Oct 2026

Scope: the whole app at v3.1.0, including the 29 Oct copy review. Methods:
- an independent bug review of the data layer and screens
- an independent security review of the database rules, API routes, client
  code and git history
- `npm audit`
- an axe accessibility scan of 18 screens
- Lighthouse (mobile) on the welcome page and a Mission page
- the existing test suites

Everything below marked **Fixed** is on branch `main-cig2ix` with tests.

## Fixed: security

1. **Next.js had a critical advisory** (remote code execution and request
   forgery in the image optimizer and `next/og`). Upgraded 16.3.1 → 16.4.3;
   `sharp` updated. `npm audit`: 0 vulnerabilities.
2. **The app could be framed by another site (clickjacking)**, for example to
   trick someone into tapping Delete Account. Added `X-Frame-Options: DENY`
   and `frame-ancestors 'none'`, plus `nosniff`, HSTS, `Referrer-Policy` and
   `Permissions-Policy` (`next.config.ts`).
3. **Anyone could flood Antonio's inbox.** Flipping "onboarding finished" back
   and forth, or deleting and re-adding the 30th Mission, re-sent the admin
   email each time, with attacker-chosen text. Now each email goes once per
   user, ever. Users can't un-finish onboarding or change their email
   column. Completed Missions can't be deleted (removal is soft).
4. **Reminders could be abused.** Backdated reminders could jam everyone's
   queue, and push "endpoints" could point the server at any URL. Now
   reminders can't be in the past and must be on your own Mission, with a
   cap per user. Endpoints must be a real push service (Google, Mozilla,
   Apple, Microsoft).
5. **Storage could be filled.** Analytics events and some record fields had
   no size limits. Now they have size caps, and analytics has a cap of 300
   events an hour per user.
6. **Records could be backdated or given fake history.** The server now sets
   the completion time and starts history empty. One-Off Actions can't carry
   photos.
7. **The notify secret lived in trigger source code** in the live database.
   It is now in a private table no app user can read. The migration reads it
   from the live database, so it never appears in this repo.

Items 3–7 are in **`supabase/migrations/0010_hardening.sql`**, which **must be
run in Supabase** the same way as 0009. It is safe to run before or after
the app deploy. Tests: `npm run test:db` (23 new checks).

## Fixed: bugs

1. **Possible endless spinner after onboarding.** If the first data load was
   still in flight when onboarding finished, the load was thrown away and
   never retried (`store.ts`). It now reloads.
2. **Settings and Mission 13 could drift apart for good.** The identity was
   saved to the profile first and then Mission 13. If the second step
   failed, retrying did nothing. Mission 13 is now saved first. Clearing the
   identity while Mission 13 exists now explains itself and puts the
   sentence back.
3. **Old (first-curriculum) Missions 21, 27 and 30 couldn't be edited.** The
   edit form demanded the new plan fields. Edits to old records now check
   only the text, as the server does.
4. **"Edited Oct 28" showed on records nobody edited.** The migration and
   remove/restore touched the update time. The label is removed; the
   timestamps are still stored, as the spec requires.
5. **One failed background refresh made Proof Log entries unopenable**, and
   showed "Couldn't load this Mission" over data already on screen. Now that
   only happens when there is truly nothing loaded, and any successful save
   clears the error.
6. **Finishing an old "in progress" action overwrote what was declared.**
   Fixed. Old numbered Missions in that state now open on their Mission
   screen, where the new rules apply.
7. **The 30/30 admin email counted removed records, and missed restores.**
   Fixed (in 0010).
8. **A redirect to onboarding could drop freshly refreshed sign-in cookies**,
   which could sign someone out later. The redirect now carries them.
9. **The walkthrough test broke** after the 29 Oct copy review renamed
   Mission 1 and reworded onboarding. Updated.

## Fixed: performance and accessibility

- Product images are now WebP: 104 KB → 31 KB for the welcome hero and
  160 KB → 31 KB for the set photo. The hero downloads first and its space
  is reserved, so nothing jumps.
- The demo banner and the buy row are now labelled page regions, and the
  onboarding progress dots have a valid label. axe now reports no issues on
  all 18 screens.

## Not changed, worth deciding

1. **Crest logo resolution.** `public/images/logo.png` is 256 px but shows
   at 240 px, so it's soft on sharp phones. Ask for a 512 px or larger
   version (transparent PNG).
2. **Mission screens wait for data before drawing anything** (Lighthouse
   LCP ~3.9s on a slow phone). Every screen reads the user's records first.
   Making it faster means drawing the Mission's text before the records
   arrive. It's a moderate change; worth doing if real users report
   slowness.
3. **A full Content-Security-Policy** (limit which sites the app may load
   from). It needs care around YouTube, Supabase and Shopify, so it wasn't
   rushed in.
4. **`middleware.ts` → `proxy.ts`.** Next 16 deprecates the old name. It
   still works. Renaming is low value and touches how Netlify runs it, so
   it's best done on its own with a staging check.
5. **Admin email for an account deleted and recreated** fires again for the
   new account. That's by design: it's a new person record.
